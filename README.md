## 手机号码为什么需要做号码标记检测？

在外呼、客服、注册风控和号码库清洗等业务中，仅凭号码归属地很难判断一个来电是否值得接听。相同号码可能在不同平台被标记为“骚扰电话”“营销推广”“广告营销”，也可能已经完成企业官方认证。若开发者逐个平台查询，不仅接入成本高，还要自行处理不同平台的返回格式。

号码标记检测 API 的价值，就是把多个号码标记平台的结果聚合成一次标准化查询。业务系统可以先获取整体结论，再根据平台状态、标签和标记量设置自己的风险规则。

## Tmini 号码标记查询 API 能返回什么？

Tmini 的手机号标记查询接口支持通过一个请求查询多个平台的号码状态，包括腾讯手机管家、360 手机卫士、百度、小米、电话邦等平台。接口返回内容主要包括：

- `isMarked`：号码是否在任一平台存在标记；
- `region`：号码归属地信息；
- `results`：各平台的查询结果；
- `status`：平台状态，例如“被标记”“未标记”“认证”或部分平台的归属状态；
- `tags`：具体标签，例如骚扰电话、营销推广、广告营销；
- `count`：部分标签提供的标记量；
- `name` 或认证名称：号码在平台完成企业认证时显示的官方名称。

需要注意，“认证”和“被标记”不是同一类结果。一个快递、银行或客服号码可能被平台认证为企业号码，如果业务只判断 `isMarked=true` 就直接拦截，容易误伤正常企业来电。

## 接口地址、请求方式和积分规则

| 项目 | 说明 |
| --- | --- |
| 接口名称 | 手机号标记查询 |
| 请求方式 | GET |
| 接口地址 | `https://api.tmini.net/apis/checkmark` |
| 鉴权方式 | Query 参数 `key` |
| 必填参数 | `key`、`phone` |
| 当前计费 | 300 积分 / 次 |
| 接口文档 | [https://api.tmini.net/detail/1](https://api.tmini.net/detail/1) |

该接口是收费接口，调用前需要在 Tmini 控制台注册账号、创建调用密钥并准备足够积分。积分不足时，接口会返回错误信息，业务系统应在调用前后做好余额和异常处理。

## 最简单的 cURL 调用示例

将 `你的密钥` 替换为控制台生成的 Key，将 `phone` 替换为待查询号码：

```bash
curl "https://api.tmini.net/apis/checkmark?key=你的密钥&phone=13800138000"
```

`phone` 只传号码本身即可，不要添加 `+86`、空格或横线。接口文档也支持带区号的固定电话示例，例如 `02131216055`，因此实际使用时应以纯数字格式传入待检测号码。

## Python 调用示例

```python
import requests

url = "https://api.tmini.net/apis/checkmark"
params = {
    "key": "你的密钥",
    "phone": "13800138000",
}

data = requests.get(url, params=params, timeout=10).json()

if data.get("code") != 200:
    print("查询失败：", data.get("msg"))
else:
    print("号码：", data.get("phone"))
    print("归属地：", data.get("region"))
    print("是否被标记：", data.get("isMarked"))

    for item in data.get("results", []):
        print(item.get("platform"), item.get("status"))
        for tag in item.get("tags", []):
            print("  标签：", tag.get("name"), "标记量：", tag.get("count", "暂无"))
```

## 号码标记检测适合哪些业务？

### 1. 外呼系统号码过滤

销售或通知类外呼前，可先检测号码是否被标记为骚扰电话、营销推广或广告营销。对高标记量号码进行跳过、限频或人工审核，减少无效拨打和投诉风险。

### 2. 客服来电识别

客服系统接到来电时，可以查询号码的标签和企业认证名称，再把结果展示给坐席。认证号码可作为正常业务线索，风险标签则可以触发提醒。

### 3. 注册与交易风控

在账号注册、登录异常或交易审核环节，号码标记结果可以作为辅助信号，与设备、IP、历史行为等数据一起参与风险评分。

### 4. 号码库清洗

对历史号码库进行定期检测，识别已经被大量标记的号码，更新号码状态和分组。相同号码的结果可以在业务侧适当缓存，减少重复调用和积分消耗。

## 积分不足或调用失败怎么办？

接口错误响应会通过 `code`、`errcode` 和 `msg` 提供原因。常见情况包括：

- `11001`：没有提供调用密钥；
- `11002`：密钥错误；
- `11004`：积分余额不足；
- `11011`：收费接口需要有效密钥；
- `11018`：请求方式不允许；
- `11023`：密钥已过期。

程序不要只依赖 HTTP 状态码，建议优先判断 JSON 中的 `code` 是否为 `200`，失败时记录 `errcode` 和 `msg`，并向用户返回可理解的提示。积分不足时，前往 Tmini 控制台充值或补充调用额度后再重试。

## 接入时的安全和合规建议

第一，API Key 只能放在服务端环境变量或密钥管理系统中，不要写入网页 JavaScript、移动端安装包、公开代码仓库和日志。第二，始终使用 HTTPS 调用，避免密钥和号码在传输过程中泄露。第三，号码标记数据存在平台更新延迟，不应作为唯一的拒绝或封禁依据。涉及用户权益的决定，建议结合人工复核和其他业务数据。第四，查询号码应符合适用的隐私、数据安全和业务合规要求。

## 常见问题

### 号码没有标记，是否一定安全？

不一定。`未标记` 只能说明当前聚合结果中没有发现对应标签，不能证明号码一定可信，仍应结合业务行为和其他风控信号判断。

### `isMarked` 为 true 是否应该直接拦截？

不建议。应继续读取 `results`，确认是骚扰、营销等负面标签，还是企业认证结果，并结合标记量设定分级策略。

### 可以把 Key 放在前端直接调用吗？

不建议。前端代码容易被查看和复制，可能导致 Key 被盗用并消耗积分。更稳妥的方式是由自己的后端服务代为调用 Tmini 接口。
